**PRODUCT IMAGES by business type:**
- Scope: **per-shop module flag** `images`, defaulted by business type, admin-toggleable (reuses the Expense-Manager module pattern — see roadmap "FEATURE SPRINT").
- Rule the user gave: images **depend on business type, BUT if the shop sells ONLINE (marketplace on) images are COMPULSORY** — an online customer must see what they're buying. So effective rule: `imagesEnabled = featureEnabled('images') || featureEnabled('marketplace')`; and `images` default = the type's marketplace default (food/retail/grocery/wholesale/books/hardware/restaurant = on; pharmacy/salon/service/workshop = off). Pharmacy walk-in = images off (neat form: salt/name only); goes on only if they enable online.
- Single vs multi: default MULTI (online listings benefit); single-mode cap is a later refinement. Product form hides the uploader when images disabled; POS/marketplace already fall back to initial-letter tiles.

**RIDERS:**
- User: "if tenant wants his own [riders] else admin-side or platform-side riders." → support BOTH, tenant-own primary, platform as the fallback.
- **Model A — tenant's own riders: BUILD NOW.** Tenant-scoped `riders` (name, phone, active); assign an online DELIVERY order to a rider; status assigned→picked_up→delivered; customer tracking status (+ optional shareable link). No rider app / GPS / WebSocket. Delivery-mode choice per tenant: pickup-only / self-delivery(own riders) / platform-riders.
- **Model B — platform rider pool: DESIGNED, LATER.** The Foodpanda-style build (separate rider app + auto-assignment engine nearest/accept/decline/cascade + live GPS + WebSocket) — the 3-app model in [[shopos-delivery-rider-flow]]. "Platform riders" shows as coming-soon until built.

**BATCH 2 — PACK-BREAKING DONE (2026-07-21). 435 backend tests green (PackBreakingTest +8), web build clean.** Pharmacy/grocery sell same stock as loose units / strips / boxes from ONE base-unit pool:
