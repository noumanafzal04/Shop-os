2026-08-26. Four screens in one batch had the same shape: **a rule applied to
one half and not the other**, where the missed half looks finished because it
is not an error state — it is a smaller true thing.

- Staff: job **presets** filtered by module/trade since day one; the nineteen
  **checkboxes they tick** never were, so a mart was offered Kitchen board.
- Orders: server accepted `channel`/`open_only`; the screen sent neither.
- Subscription: eleven modules in the map, **three** named on screen (labels
  were a lookup table in the panel) — a restaurant was never told it had dine-in.
- Sales: the CSV export honoured filters the screen could not set.

**How to apply:**
- When you filter one half of a screen, ask out loud what the OTHER half is.
- **Filtering a list of choices is safe; filtering a list that is also the
  SUBMITTED state is a silent edit.** Flag rows as unavailable, never drop them
  — the form submits what it drew. Same trap as `categoryOptions(keepId)`.
- Before writing a filter, check what the endpoint already accepts. Four
  endpoints were richer than their screens.
- Labels/options that exist server-side must come FROM the server. A second
  copy in the panel is what produced the subscription gap.
