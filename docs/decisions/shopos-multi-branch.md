Multi-branch architecture decided 2026-07-23 (design locked, NOT built — this is Step ④ in the revamp flow, after [[shopos-businessos-roadmap]] Step ① plans/limits which owns the `max_branches` cap).

**Core model:** a branch lives *inside* the tenant, not a separate account.
- Tenant = the business/account. Branch = a physical location under it.
- **Every tenant always has one branch** — a default "Main" created silently at setup. Single-shop owners never see branch UI.
- **No dual code path**: "going multi-branch" is just raising `max_branches` on the plan. No data migration.
- Plan allows 1 branch → behaves exactly like today (invisible branch). Allows N → Branches page + HQ dashboard appear.

**What's shared vs per-branch:**
- Shared (tenant-level): product catalog, categories, suppliers, customers, plan.
- Per branch: stock levels, sales/orders, cash registers, expenses, staff assignment, dine-in tables, purchases.

**Locked decisions:**
- **Per-branch stock** (chosen over shared pool). Inventory becomes `product × branch → qty` — the heaviest part; ripples through `InventoryService` (single write-path), FEFO/expiry, low-stock alerts.
- **Branch-to-branch transfers** (A→B, reduces A / increases B, audit trail).
- **Cross-branch stock lookup** (the "Bata" feature): from a branch (esp. when out of stock in POS), "Check other branches" shows Branch→qty across all branches, then one-tap "Request transfer" from a branch that has it. Same inventory data, surfaced two extra ways.
- **Per-branch pricing**: effective price = `branch override ?? tenant base` (admin-set).
- **User ↔ branch access**: users get a branch assignment (owner=all; manager/staff=one) + a "current branch" session context mirroring tenant scope. Managers/staff can *look up* other branches but only *operate* their own.
- **HQ dashboard + scope switcher**: All-Branches (owner only — rollup + per-branch comparison) ↔ single branch. HQ view doesn't render for single-branch tenants.

**Build needs:** `branches` table + `branch_id` on branch-scoped tables; per-branch InventoryService; transfers entity; cross-branch lookup view; branch access/context; per-branch price overrides; consolidated reporting; `max_branches` gate.
