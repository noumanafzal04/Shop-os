On 2026-07-13 the user expanded ShopOS from "POS + marketplace" to a full **Business Operating System** (ERP-lite + POS + commerce + marketplace + service marketplace, multi-tenant SaaS). We agreed to build it in phases, module by module, with the same rigor (thin controllers → Actions → tests). User approved **fresh migrations** ("we're in start phase") — no prod data to preserve, so schema can be restructured cleanly.

**Catalog model (agreed):** Business → Business Type → Catalog → Categories → Subcategories → Collections → Items → Variants → Attributes → Modifier Groups (food) → Modifier Options → Add-ons → Inventory → POS → Marketplace. Every Item has an **item_type** unlocking a capability matrix:
- physical_product: inventory required, variants yes, modifiers no, addons yes, pos+marketplace yes
- food_item: inventory optional, variants yes, modifiers yes, addons yes
- medicine: inventory required, variants yes, no modifiers/addons
- service: no inventory, variants optional, pos optional

**Phase 1 — Catalog Foundation: DONE.** `App\Support\ItemTypes` capability registry; `BusinessTypes::itemTypesFor()` maps business→allowed item types; products gained `item_type,barcode,brand,unit,attributes(json),discount_price,tax_rate`; coarse `type` (product|service) kept & derived from item_type (avoids breaking sales/orders/inventory which key on it). Unlimited category nesting (`childrenRecursive`) + reorder endpoint (`POST categories/reorder`) + visibility. New `collections` + `collection_item` pivot (no surrogate PK). Endpoints: `/item-types`, `item_types` on `/business-types`, collections apiResource. Web: rewrote CategoriesPage (unlimited tree, add-sub, reorder ↑↓, hide/show), new CollectionsPage (`/tenant/collections`), product form now item-type-driven (selector from allowed types, brand/unit/barcode, collections chips). 255 backend tests pass.
